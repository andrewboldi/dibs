# dibs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build dibs, a single-machine job scheduler where coding agents reserve CPU cores, RAM and
VRAM with a time estimate, jobs run shortest-first without starving long ones, reservations are
enforced, and GPU use outside dibs is stopped.

**Architecture:** A stdlib-only Python package. A daemon (asyncio, Unix socket, SQLite) owns the
queue, re-plans every second with a pure planner (priority tags + conservative backfill), launches
each job through a small shim (inside a memory-capped systemd scope when available), and polls the
GPUs through NVML to watch VRAM and run the guard. The `dibs` CLI talks to the daemon and starts it
on demand. `dibs setup` installs a user service and writes instructions into every installed agent
CLI's global instructions file.

**Tech Stack:** Python ≥ 3.11 standard library (asyncio, sqlite3, ctypes, tomllib, argparse),
pytest, uv, hatchling, GitHub Actions; asciinema + agg for the demo.

**Spec:** `docs/superpowers/specs/2026-11-13-dibs-design.md` (section numbers below refer to it).

## Global Constraints

- Python `>=3.11`. Runtime dependencies: none. Dev dependency: `pytest>=8`.
- Linux is supported; on macOS the package must import and run but skips pinning, RAM caps and the guard.
- No root. Tests and development never write to the real `$HOME`, real agent instruction files or
  real systemd units, and never run a daemon that can see the real GPUs with the guard on. Tests set
  `DIBS_HOME` to a temp dir, `DIBS_GPU_BACKEND=smi` with the fake `nvidia-smi`, or an in-process
  `FakeBackend`; anything touching the real GPU uses `guard = "warn"` or `"off"`.
- Sizes are binary (`G` = GiB). Durations: `90s 20m 1h 1h30m 1.5h 2d HH:MM:SS MM:SS`; bare number = minutes.
- Job environment additions (section 8.2): `CUDA_VISIBLE_DEVICES`, `CUDA_DEVICE_ORDER=PCI_BUS_ID`,
  `OMP_NUM_THREADS MKL_NUM_THREADS OPENBLAS_NUM_THREADS NUMEXPR_NUM_THREADS VECLIB_MAXIMUM_THREADS`
  (unless already set), `PYTHONUNBUFFERED=1` (unless set), `DIBS_JOB_ID DIBS_CPUS DIBS_MEM DIBS_VRAM
  DIBS_GPUS DIBS_INSTANCE`.
- CLI exit codes: 0 ok; 1 error; 2 usage error or rejected request; 124 `wait` timeout; 130 job
  cancelled (or `run` interrupted); otherwise the job's own exit code.
- JSON output never includes a job's environment.
- Environment variables dibs reads: `DIBS_HOME`, `DIBS_GPU_BACKEND` (`nvml|smi|none`),
  `DIBS_FAKE_GPU_FILE` (fake nvidia-smi only), `DIBS_NO_SYSTEMD=1`, `DIBS_SESSION`,
  `DIBS_BUILD_OVERRIDE` (tests only), `CLAUDE_CODE_SESSION_ID`.
- Commits: plain-sentence subject, a body saying why, trailer
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Push after every task.

## Review Focus

1. Arguments after `--` that look like flags, contain spaces, quotes or non-ASCII, or are empty
   strings must reach the job exactly as given → Task 11 `test_run_preserves_argv`.
2. A `DIBS_HOME` deep enough that the socket path exceeds the 108-byte AF_UNIX limit must still
   work → Task 6 `test_long_home_uses_short_socket`.
3. A job submitted from a shell that is then killed, as an agent's tool timeout does, keeps running
   and the daemon survives → Task 11 `test_job_survives_submitter_death`.
4. A CLI from a newer build talking to an older daemon restarts it rather than misbehaving → Task 11
   `test_build_mismatch_restarts_daemon`.
5. A job whose directory vanished before it started, or whose command doesn't exist, fails or is
   rejected with a clear reason and the daemon keeps serving → Task 9
   `test_missing_cwd_fails_cleanly`, Task 11 `test_submit_rejects_unknown_command`.

### Task 3: The planner

**Files:** Create `src/dibs/planner.py`, `tests/test_planner.py`

**Interfaces:**
- Consumes: `Capacity, Request, fits_machine` (Task 2), `format_size` (Task 1).
- Produces:
  - `@dataclass(frozen=True) Running(job_id: int, request: Request, cpu_ids: tuple[int, ...], gpu_ids: tuple[int, ...], started: float)`
  - `@dataclass(frozen=True) Queued(job_id: int, request: Request, tag: float, submitted: float)`
  - `@dataclass(frozen=True) Start(job_id: int, cpu_ids: tuple[int, ...], gpu_ids: tuple[int, ...])`
  - `@dataclass(frozen=True) Prediction(job_id: int, position: int, start: float|None, end: float|None, gpu_ids: tuple[int, ...], reason: str)`
  - `@dataclass(frozen=True) Plan(starts: list[Start], predictions: dict[int, Prediction], running_ends: dict[int, float])`
  - `OVERRUN_MIN = 60.0`, `OVERRUN_FRACTION = 0.10`
  - `expected_end(job: Running, now: float) -> float`: `started + time` if that is after `now`,
    else `now + max(OVERRUN_MIN, OVERRUN_FRACTION * time)`.
  - `plan(capacity: Capacity, running: Sequence[Running], queued: Sequence[Queued], now: float) -> Plan`

**Algorithm** (spec 7.2). Keep a step-function profile of free resources: sorted segments
`[t_i, t_{i+1})`, each with free CPU count, free RAM and free VRAM per GPU index; the last segment is
open-ended. Initialise from capacity minus running jobs at `now`, giving resources back at each
running job's `expected_end`.

```
order = sorted(queued, key=lambda q: (q.tag, q.submitted, q.job_id))
for position, q in enumerate(order, 1):
    if err := fits_machine(q.request, capacity):
        prediction(start=None, reason=f"can't fit this machine: {err}"); continue
    for each segment start t (ascending, t >= now):
        window = [t, t + q.request.time)
        over the segments the window overlaps: min free CPUs, min free RAM, min free VRAM per GPU
        eligible = GPUs whose min free VRAM >= request.vram
        if CPUs, RAM fit and len(eligible) >= request.gpus:
            gpus = request.gpus GPUs from eligible with the least min free VRAM (ties: lowest index)
            subtract the request from every segment in the window (splitting at its ends); record; break
    if t == now: Start(job, cpu_ids=lowest CPU ids not held by running jobs or earlier Starts, gpu_ids=gpus)
```

Reason for a job whose start is after `now`: compare the request with what is free at `now` given
running jobs only. Name every short resource, joined by `"; "`: `"needs 8 CPUs; 4 free"`,
`"needs 16G RAM; 8G free"`, `"needs 6G VRAM; most free on a GPU: 2G"` (multi-GPU:
`"needs 2 GPUs with 6G VRAM free; 1 has"`). If nothing is short, it is waiting on a reservation:
`"would delay #7, which is ahead in line"`, naming the first higher-priority job whose planned
window overlaps `[now, now + time)`. Jobs starting now have reason `""`.
